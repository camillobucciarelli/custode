# injectable for dependency registration

Custode is being aligned to the stack and architecture of the owner's other Flutter app, Postino (repo `email-client`), so conventions and agent skills are shared between the two. Implementation starts only after store approval of 1.0.0 and completion of spec 023.

`get_it` registrations are generated by `injectable` and `build_runner` instead of being written by hand in four registration files. The generated code is committed, and CI fails when running codegen produces a diff. This is the Postino convention.

## Considered Options

- Keep manual registration: rejected, it diverges from the Postino convention.
